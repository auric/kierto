Status: approved, not started, 2026-10-11. BRIEF section 2 "Release 2" defines the scope. The user runs docs/smoke-r2.md before release. Line references (file.ts:N) point to the code at the plan date.

Build order: WP0 contracts first, then server packages, then UI packages. After WP0, server packages edit only their own files, except jobs.ts (S-RR, then S-ASK).

## 1. Cross-cutting decisions

- Ask uses the same single run slot as reviews: the runner keeps one process and throws when one is active (claude.ts:230); pruneWorkspaces deletes every run folder and is safe only with no run active (workspace.ts:338, jobs.ts:504-508); two runs on one PR would race on forced refs refs/rl/<id>/* (workspace.ts:241-252).
- Run kinds: a re-review stays kind='review' with since_head set (drafts UI follows the newest review run: model.ts:192, useReview.tsx:89-92). Ask is a new kind 'ask'.
- Untrusted data: every new text reaches the model only as a file in context/ under the UNTRUSTED banner (workspace.ts:186-188): task.md (Jira), findings.md (re-review). Prompts carry only IDs and the user's own text. WP0 widens the TRUST rule (catalog.ts:147-150) to "every file in ./repo and ./context".
- No diff library. The diff viewer uses diffmap rows plus the existing excerpt CSS. Remove the @pierre/diffs line from BRIEF §7.
- Network only on a user action: Jira calls only on a Settings save or a Fetch click. Diff git fetch only on "Get the code" (a review run also fills the cache). Sync polling adds no request.
- The review_run rebuild: SQLite cannot change a CHECK, and three tables point to review_run with ON DELETE CASCADE (007_review.sql:42,59; 008_post.sql:9). db.ts must run migrations with foreign keys off, then PRAGMA foreign_key_check (SQLite lang_altertable.html, "Making other kinds of table schema changes").

### S-RR. Re-review server (workspace.ts, jobs.ts, validate.ts, prompt.ts, items.ts, routes.ts)
- Base run: newest run with kind='review', status completed or incomplete, and COALESCE(explain, profile='explain') = 0. 409 when no base run, when since_head equals the PR source head, or when the brief profile is Explain. Idempotency key: pr:"rereview":baseRun:src:tgt:profile:rev:noteHash.
- Range base: T = git merge-tree --write-tree --no-messages <since> <MB_new>. If T equals the tree of <since>, range base = <since>. Else range base = git commit-tree T -p <since> -p <MB_new> with a fixed identity and date (deterministic hash). A conflict (exit 1), a missing since object, or any git error falls back to full range: base = MB and since.incremental = false. After a run with results, git update-ref refs/rl/<id>/reviewed <head> keeps the reviewed head from gc.
- Two diffs: context/changes.patch and files.txt show rangeBase..head. ws.diff (validator diff) stays MB..head. Posts anchor fromHash = target, toHash = source (I8). plan.ts:77-97 picks inline/general from the validator excerpt. git MCP BASE is the range base; its alias skips the ancestry check (git-mcp.ts:88-91).
- Carried items: carry the base run's findings and questions with status new or accepted. The prompt lists only their IDs. findings.md (through files) holds path, side, lines, indented anchorText, severity, body. validateEarlier() (pure) reuses validate() against MB..head using the row's current line, payload anchorText, and any verdict path/line override. Rules: unknown or duplicate ID → coverage.skipped; missing verdict → open plus a skipped line (run incomplete); "open" with no anchor → outdated; fixed and outdated keep the anchor if the code is still there.
- Run end in one transaction (like SQL.supersede, jobs.ts:203): re-read each source row and skip it if its status changed during the run; insert the copy (open findings keep source status, body and edited flag; fixed/outdated copies get status discarded; payload gets carried); mark source row discarded with revision+1. Insert order: new findings, open carried, questions, closed carried. A base run that was incomplete adds a notChecked line.
- items.ts: a finding with no anchor refuses accept, edit, restore and move with 400.
- Tests (tests/review/rereview.test.ts, fake CLI, temp repos): fast-forward → changes.patch holds only the new commit's file, ws.diff the full change; rebase and target-into-source merge exclude target-only files; conflict and missing object fall back to full range; 409 cases and idempotency; shared slot; open re-anchored as moved; fixed → discarded; open with code gone → outdated; missing verdict → incomplete; unknown ID dropped; supersede raises revision; item posted during the run is not carried; accepted and edited carry with flags; the post plan posts a carried item once at the new heads; restore without anchor 400; no finding body in stdin; git MCP argv has --base=<range base>; the reviewed ref moves.
