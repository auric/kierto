# M1 plan: inbox, sync, read state, notifications, minimal settings

Status: draft, 2026-10-09. Scope: BRIEF section 2 "M1", US1 to US4, and the URL and token part of US9. Gate 0 is complete. Where integration-check.md and BRIEF section 7 differ, integration-check.md wins.

## 1. Scope

- In: discovery of open PRs where I am reviewer or author, and follow by URL. Polling sync, per-message read state, and opt-in browser notifications.
- In: settings for the Bitbucket URL, the token, and an optional CA file. The three panes of prototype/index.html, the M1 keys, and the M1 UI states. Multi-tab safety and Playwright acceptance against fixtures.
- Out: review runner, Explain, triage, publish, replies, profiles, the poll-interval setting, and `bun build --compile`. The Review and Run log tabs exist but are disabled, with the note "Arrives in M2". Only the ForgeProvider boundary exists in M1. ReviewRunner and ContextSource wait for M2.

## 2. Cross-cutting decisions

| Topic | Decision | Reason |
|---|---|---|
| Fixture provider | A fake Bitbucket HTTP server (`tests/support/fake-bitbucket.ts`) replays fixtures. All tests run the real REST adapter against it. | One code path for paging, headers, errors, and timeouts. No second provider to keep in step. |
| Port | Fixed default port 7317. `REVIEW_LOOP_PORT` overrides it. A busy port stops the start with a clear message. | Notification permission and localStorage are per origin. A random port loses both. |
| Mutation guard | A Host and Origin check runs on every request. Every mutation also needs the `X-RL-Session` header. `csrf()` stays mounted as a second layer. | Hono `csrf()` checks only form content types (I10). The JSON API needs the header check. |
| Session token | 32 random bytes per process start. Production puts it in a meta tag of the served index.html. | BRIEF 3.6: the server puts the token into the page it serves. |
| CORS | No CORS middleware. No `Access-Control-Allow-*` header on any response. | BRIEF 3.6. |
| SSE | `streamSSE`, `idleTimeout: 30` in `Bun.serve`, and a heartbeat every 15 s. `stream.onAbort` removes the subscriber. | Bun closes idle connections after 10 s, also during a stream (I11). |
| Outbound HTTP | Bearer token, `redirect: "manual"`, and any 3xx is an error. `AbortSignal.timeout(30 s)`. `tls.ca` from the configured CA file. Never `rejectUnauthorized: false`. | BRIEF 3.6. Gate 0 saw no redirect. `tls.ca` is the documented Bun fetch option. `NODE_EXTRA_CA_CERTS` is not verified for Bun. |
| URL scheme | https only. http only for loopback hosts, which the fake server uses. | The token must not travel in clear text. |
| Database | One SQLite file per instance origin: `<dataDir>/db-<first 16 hex of sha256(origin)>.sqlite`. | Comment identity includes the instance, with no instance column in every key. |
| Read state | Column `ack_version` on `comment`, not a separate table. The first-sync import and own comments set `ack_version = version` in the same write. | One rule for unread: `ack_version IS NULL OR ack_version < version`. No flag columns. |
| Events | New `event` table with `UNIQUE(pr, kind, ref)`. It replaces `activity_seen`. | Edits, replies, and deletes create no new activity ID (I1 to I3). Dedupe and digest need durable per-event state. |
| Sync write unit | One transaction per PR, only after a complete activities fetch. A partial fetch writes only the checkpoint error. | A6: the previous state stays. The checkpoint advances in the same transaction as the data. |
| Acknowledgement | A message counts as read when 50% of it is visible in the detail pane. The browser tab must be visible too. | Precise meaning of "the messages that the tool showed me". Native IntersectionObserver. |
| Notifications | A server-side atomic claim gives each event to one tab only. One notification per PR, with `tag` = PR key. | Multi-tab dedupe and dedupe after a reload, with no browser-side coordination. |
| Markdown | `react-markdown` without raw HTML. Images render as links. A CSP with `img-src 'self'` blocks remote images. | BRIEF 3.6: safe Markdown, no automatic external images. |
| Fonts and avatars | System font stack. Initials, no remote avatars. | Local-first: the UI makes no request to other hosts. |
| Gate per group | `bun run typecheck` (`tsc --noEmit`, strict) and `bun test`. No linter in M1 (D5). | No lint config exists. |
| Test isolation | Every test sets `REVIEW_LOOP_SECRETS=memory` and a temp `REVIEW_LOOP_DATA_DIR`. | Tests must never read or overwrite the stored token under service `review-loop`. |

| Follow state | Polling | Shown in |
|---|---|---|
| followed | Activities on every cycle. | Role views while open. Needs you per its rule. Following. |
| unfollowed | Dashboard data only. No unread, no events. | Role views while on the dashboard, with the text "Not followed". |
| archived | None. | Nowhere. An undo toast or follow by URL restores it. |

## 3. Invariants and evidence

- I1. Only `commentAction: ADDED` exists. An edit changes the activity in place and increments `comment.version` (integration-check.md:46,48; `activities-after-edit.json`).
- I2. A reply has no activity and no `parent` field. It is in the parent's `comment.comments[]` (integration-check.md:47; `activities-nested-reply.json`).
- I3. A delete removes the activity. GET of the comment returns 404. No tombstone exists (integration-check.md:49; `comment-get-after-delete-404.json`, `activities-after-delete.json`).
- I4. On the last page, `nextPageStart` is absent (dashboard, activities) or null (changes) (integration-check.md:43; `activities-opened-only.json`, `pull-request-changes.json`).
- I5. `X-AUSERNAME` equals the token owner slug. The probe recorded it on every response (integration-check.md:42; bitbucket-probe.ts:77).
- I6. A reviewer entry has `user`, `lastReviewedCommit`, `role`, `approved`, and `status` (raw `03-dashboard-REVIEWER.json`, keys only; not yet sanitized).
- I7. The dashboard returns only OPEN PRs. A merged PR needs the single-PR GET (integration-check.md:44; BRIEF.md:277).
- I8. Activity order is not by ID or by time (`activities-inline-anchored.json`: 10000003, 10000001, 10000002). Code never depends on order.
- I9. Bearer auth works, and the server sent no redirect (integration-check.md:41). Bun.secrets works on Windows; Linux is not checked (integration-check.md:15,66).
- I10. Hono `csrf()` validates only unsafe methods with form content types (hono.dev/docs/middleware/builtin/csrf).
- I11. `Bun.serve` closes a connection after 10 s with no bytes, also mid-stream (bun.com/docs/api/http, idleTimeout).

## 4. Data model (M1)

- `pull_request(id INTEGER PK, project, repo, pr_id, UNIQUE(project, repo, pr_id), title, description, author_slug, author_name, my_role, my_status, last_reviewed_commit, state, pr_version, source_head, target_head, source_branch, target_branch, web_url, updated_date, on_dashboard, followed, archived_at, initialized_at)`.
- `comment(pr, comment_id, PK(pr, comment_id), version, parent_id, root_id, author_slug, author_name, text, anchor_json, thread_resolved, created_at, updated_at, ack_version, tombstoned_at)`. A root comment has `root_id = comment_id`.
- `sync_checkpoint(scope PK, last_complete_at, incomplete_reason, last_error, updated_at)`. Scopes: `dashboard` and `pr:<id>`.
- `event(id INTEGER PK, pr, kind, ref, created_at, digest, claimed_at, UNIQUE(pr, kind, ref))`. Kinds: `comment_new` (ref = comment ID), `commits_pushed` (ref = source head), `reviewer_added` (ref = PR `version`).
- Differences from BRIEF section 7: no `activity_seen`, no `acknowledgement` table, a new `event` table, and no `instance` column. Section 2 gives each reason.

Every route module also chains its handlers, or `hc` infers empty types. `api.ts` builds `hc<AppType>` and adds the session header.

The guard accepts the Vite origin only when `REVIEW_LOOP_DEV_ORIGIN` is set. Dev has no CSP, because Vite needs inline scripts.
- Scripts: `dev`, `build`, `start`, `typecheck`, and `test`. Pin exact dependency versions.
- Tests first (`app.request()`): a wrong Host gives 403. A foreign Origin gives 403. A mutation without the token gives 403. A mutation with the token gives 200. A stale token gives `session_stale`. A cross-site navigation to `/` passes.
- Tests first: no response has `Access-Control-Allow-Origin`. A started server reports hostname 127.0.0.1. An SSE client gets a broadcast and a heartbeat, and abort removes it.
- Scenarios: none directly; G1 is the base for A14. Done: tests green, `bun run start` serves the page with the meta token, and `bun run dev` serves with HMR.

### G4. Sync engine (about 850 lines)

- Skills: none. Tier: implementer-xhigh. Goal: correct unread state and events under edits, deletes, paging, partial data, sleep, VPN loss, and restart.
- Files: `src/server/sync/{engine.ts, reconcile.ts}`, `tests/sync/`, and one start call in `src/server/main.ts`.
- Step 1: fetch the dashboard for REVIEWER and for AUTHOR. When both are complete, upsert the PRs and set `on_dashboard`. A new PR starts as followed.
- Step 2 runs only after a complete dashboard; otherwise the roles and states stay. Each followed PR that is not on the dashboard gets a single-PR GET. Store MERGED or DECLINED and the new role. A 404 or 403 sets a per-PR reason.
- Step 3: each followed, non-archived PR gets `listComments`. An incomplete result writes only `incomplete_reason` and `last_error`.
- Step 4: stored live comments that are absent from a complete result are delete candidates. Each gets `commentStatus` under the same semaphore. Only a 404 tombstones. A 200 keeps the comment and records a gap. Any other result keeps it for the next cycle.
- Step 5: one transaction per PR upserts comments, tombstones confirmed deletes, inserts events, sets `initialized_at`, and advances the checkpoint.
- The upsert uses `ON CONFLICT ... DO UPDATE ... WHERE excluded.version > comment.version`. So a lower or equal version never overwrites (A3).
- The upsert sets `ack_version = version` when the PR has no `initialized_at` or the author is me. So the first sync is silent, and own comments never become unread.
- Step 6: after the commit, the engine updates its in-memory status and broadcasts `changed` with the PR IDs. Nothing outside the database runs before the commit.
- Event `comment_new`: a new comment ID, not by me, on an initialized followed PR. The thread must hold a comment by me, or my role must be AUTHOR.
- Event `commits_pushed`: the source head changed, my role is REVIEWER, `lastReviewedCommit` is set, and the PR is initialized.
- Event `reviewer_added`: my role becomes REVIEWER after the first complete dashboard. The dashboard step writes it in its own transaction. An edit makes a message unread but creates no event, because US3 names no edit case.
- Scheduling: a `setTimeout` chain with no overlap. The engine exports `syncNow()`, which the route and the e2e control call. The delay is 60 s times a random factor from 0.9 to 1.1. `POST /api/sync` starts a cycle now, or one more cycle after the running one.
- Backoff: after a cycle with only network errors, the delay doubles up to 15 min, with full jitter. Success resets it. A Retry-After value wins. A 401 pauses polling until the settings change.
- Digest: events get `digest = 1` in the first cycle after start. They also get it when the gap since the last complete cycle exceeds 120 s. The clock is a parameter, so tests simulate sleep without waiting.
- Sync logic never compares server timestamps with the local clock. Unfollow clears `initialized_at`, so a later follow imports the missed history silently. Archive and unfollow stop activity polling.
- Tests first: the first sync of another user's comments gives 0 unread and 0 events. A new reply by that user gives 1 unread and 1 event. A new engine on the same database keeps that state and adds no event (A1).
- Tests first: duplicate and reordered activities give no duplicates (A3). An edit from version 0 to 1 updates the text. The message becomes unread, and no event appears (A4).
- Tests first: absent plus 404 tombstones. Absent plus 200 keeps the comment with a gap. Absent plus a network error keeps it (A4).
- Tests first: a failure on page 2 changes no data, records the reason, and tombstones nothing. The next cycle completes (A6). Multi-page threads with both last-page forms keep every message (A5).
- Tests first: a PR that leaves the dashboard as MERGED stays followed and keeps its unread messages (A15). Own comments give no unread and no event.
- Tests first: a SQLite trigger with `RAISE(ABORT)` on the event insert rolls back the PR transaction. The checkpoint and the comments stay unchanged.
- Tests first: requests in flight never exceed 2. Offline backoff grows and resets. A simulated gap sets the digest flag. A 401 pauses polling.
- Done: every rule above has a test, and all tests use the fake server. Risk: the polling cost grows with followed PRs (R1).
### G5. Inbox rules, read state, follow, notification claim (about 650 lines)

- Skills: `hono`. Tier: implementer. Goal: the server exposes the inbox, the PR detail, and idempotent mutations that are safe from two tabs.
- Files: `src/server/inbox/{queries.ts, routes.ts}`, `src/shared/views.ts`, types in `src/shared/dto.ts`, `tests/inbox/`, and one route line in `src/server/app.ts`.
- `GET /api/prs` lists non-archived PRs that are followed or on the dashboard. Each row has role, state, status, unread count, reasons, last activity, follow state, and check status.
- `GET /api/prs/:id` gives the PR, its comments with unread flags, and its checkpoint. `GET /api/status` gives the sync state.
- Mutations: `POST /api/read`, `POST /api/prs/:id/follow`, `POST /api/prs/:id/archive`, `POST /api/follow` (by URL), `POST /api/sync`, `POST /api/notifications/claim`.
- The unread count covers followed PRs only. It counts comments that are not tombstoned, with `ack_version IS NULL OR ack_version < version`.
- Reason `reply_to_you`: an unread comment in a thread that holds a comment by me. Reason `closed`: state MERGED or DECLINED.
- Reason `new_commits`: role REVIEWER, PR open, and `last_reviewed_commit` set and different from `source_head`. The text is "New commits since your review" (D3).
- Reason `review_requested`: role REVIEWER, PR open, status UNAPPROVED, and no `last_reviewed_commit`.
- `views.ts` holds pure view predicates for the UI. Needs you: followed, and unread above 0 or (open, REVIEWER, status not APPROVED), as in prototype/index.html:433.
- Reviewing: open, role REVIEWER, and on the dashboard or followed. My PRs: the same with role AUTHOR. Following: every followed PR in any state (D1). Sort: unread first, then the newest activity (prototype/index.html:542).
- `POST /api/read` takes `{ pr, items: [{ id, version }] }`. It raises `ack_version` only to a value that is not above the stored version. So an ack never covers a newer version or a comment that the UI did not send (A2).
- Claim runs `UPDATE event SET claimed_at = ? WHERE claimed_at IS NULL RETURNING ...`. SQLite runs it atomically, so each event goes to one tab. At startup, the server deletes claimed events older than 30 days.
- `POST /api/follow` parses the URL with `pr-url.ts` and refuses a foreign origin before any request. Follow also clears `archived_at`.
- Every mutation broadcasts `changed`. zValidator with zod checks every input.
- Tests first: an ack for version 0 leaves a version-1 comment unread. A comment absent from the payload stays unread. An older ack after a newer one changes nothing (A2).
- Tests first: two concurrent claims return each event once (A14). Follow, unfollow, and archive twice give the same state. A bad payload gives 400.
- Tests first: follow by URL with a foreign origin gives 400 and sends no request. View predicates and reasons pass on fixture-built rows, including a merged PR with unread messages (A15).
- Done: all endpoints are typed through `AppType` and tested. Risk: the view rules can differ from what the user expects; D1 and D2 ask the user.

## 8. Risks

- R1. Each followed PR costs 1 to 2 requests per minute. 100 followed PRs give about 3 requests per second, with at most 2 in flight. Archive and unfollow reduce it.
- R2. A long PR needs several activity pages on every poll. No cursor catches edits (I1, I2).
- R3. A browser allows about 6 HTTP/1.1 connections per origin. Each tab holds one SSE connection, so more than 5 tabs can stall.
- R4. The meaning of `lastReviewedCommit` is not verified (U2). The "New commits since your review" reason can be wrong.
- R5. The fixtures for paging, duplicates, reordering, and other users are synthetic. Only the smoke test confirms them.
- R6. `react-markdown` is a new dependency on the untrusted-input path. Keep raw HTML off and the CSP on.

## 9. Open decisions for the user (recommended default first)

- D1. Where do closed and URL-followed PRs show? Default: a fourth view "Following". Alternative: closed PRs stay in Needs you until archived.
- D2. Archive semantics. Default: archive hides the PR and stops polling. The undo toast or follow by URL restores it.
- D3. "+N commits since your review". Default: show the text without N in M1. Add N after the smoke test records RESCOPED or the commits endpoint.
- D4. Markdown. Default: `react-markdown` without raw HTML. Alternative: plain text and no new dependency.
- D5. Lint. Default: no linter in M1, because strict typecheck and tests gate each group. Alternative: add Biome in G1.
- D6. Fonts. Default: the system font stack. Alternative: self-host the prototype fonts with `@fontsource` packages.
- D7. Port. Default: 7317. Any fixed port works, but a change resets the notification permission.
- D8. Deleted messages. Default: they count as read and show without their text.
- D9. Acknowledgement trigger. Default: 50% visible in the viewport. Alternative: every unread message rendered at open counts as read.
